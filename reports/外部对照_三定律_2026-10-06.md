## 一、C5 的直接答案：账号级复用已被产品化

**DeepInfra「Prompt Cache Retention」**（2026 年上线的显式保留特性）：

- 请求带 `prompt_cache_key`（会话/agent 等稳定标识）+ `prompt_cache_options`
  `{"mode":"explicit","ttl":"5m"|"1h"}`，即可把上下文**按账号作用域**保留指定时长
- 官方原话："Retention is **scoped to your account**"
- 配套 `prompt_cache_breakpoint`（只保留稳定前缀、忽略可变尾部）、TTL 续期语义
  （长窗内的短 TTL 不缩短窗口）
- 定价：保留 5 分钟 = 1.25× 输入价，1 小时 = 2.0× 输入价；复用走 cache-read 折扣

**因此**：把"缓存跨会话/跨进程存活"称作由本仓库率先提出的概念不成立。三定律之三的表述应改为：
**对 provider 无保证缓存行为的一手实测与编排纪律**——我们把"账号级复用"当作可依赖的
工程事实来度量并设计用法（保持 key 稳定、把复用当作收益来源而非正确性前提）。

## 二、三定律逐条对照

### 定律一（滞后窗）与定律二（块级匹配）：与公开口径一致，我们提供一手数字

- 块级管理是自托管推理的事实标准：vLLM PagedAttention 按固定块（典型 16/32 token）
  管理KV，前缀共享在块粒度进行——与我们的"64-token 块粒度、分歧截断到块边界"同构
  （块大小由实现决定，量级一致）
- 前缀匹配是**从第 0 个 token 起的精确匹配**："单个 token 改动会静默摧毁整次命中"
  ——与我们的块级截断口径一致
- Anthropic 的回本口径：写入加价 25%、读取 9 折、**每 1.4 次命中回本一次写入**——
  可直接并入 C3 的映射表

### 定律三（账号级复用）：一手实测仍然有效，概念表述需让位

第三方 2026-08 汇总的 provider 公开 TTL 口径：

| 服务 | 公开生命周期 | 备注 |
|---|---|---|
| OpenAI（GPT-5.6+） | 30 分钟，命中刷新 | `prompt_cache_options.ttl` 目前仅支持 30m |
| OpenAI（较早模型） | 空闲约 5-10 分钟，最长约 1 小时 | 部分模型另有最长 24 小时策略 |
| Anthropic | 默认 5 分钟，命中刷新 | 可付费选 1 小时 |
| Gemini（隐式） | 未公开固定 TTL | 建议把相似请求安排在邻近时间 |
| Gemini（显式） | 默认 1 小时，可自定义 | 存储另行计费，读取约 25% 价 |
| **DeepSeek** | **通常数小时到数天** | 磁盘缓存、best-effort、无固定保证 |

我们实测的"跨进程/会话存活数小时"与该表 DeepSeek 行**相互印证**。
差异在于：第三方把 DeepSeek 行标注为"无固定保证、接入时需重新核对"——
这与我们把账号级复用当**收益来源而非正确性前提**（允许随时 miss 并完整重算）的
纪律是同一件事的两种说法。

## 三、其他可吸收的外部实践

1. **真实案例（ProjectDiscovery）**：把动态工作记忆从 system prompt 挪到末尾的
   user message，命中率 **7% → 84%**，LLM 成本降 59%，累计 9.8B token 走缓存。
   这是"前缀纪律"最有力的第三方案例，可进 README。
2. **口径纪律**：成本看板必须把输入 token 拆成 cached / uncached——否则流量下降会
   被误读成缓存收益。与 C2 的口径工作互证。
3. **vCache（arXiv 2502.03771）**：语义响应缓存带每提示学习的相似度阈值与
   用户自定义错误率保证——Tier3 响应缓存的一个有理论口径的参照。
4. **回本门槛的经验值**：稳定前缀负载下命中率低于约 30% 时写入加价可能倒挂；
   低于 60% 说明结构性问题。可作为 `hitrate_budget` 场景表的交叉校验参考。

## 四、诚实标注

- 各 provider 的 TTL/定价随时间变动，上表为 2026-08 第三方汇总 + 本轮检索（2026-10-06）
  交叉核对；**接入前须以官方文档复核**（第三方原话亦是如此提醒）。
- DeepInfra 的账号级保留与我们的"账号级复用"实测处在不同层：他们是显式契约（付费换保证），
  我们测的是 best-effort 行为。两者不矛盾，但不能混为一谈。
